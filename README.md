## Overview
The Allora Prediction Platform is a single-page dashboard that compares live market data against oracle-powered forecasts generated by the Allora Network. Users can explore supported trading pairs, switch between multiple timeframes, and inspect the latest prediction output in seconds. The interface is optimised for fast iteration when demonstrating or testing Allora oracle topics.

## Features
- **Interactive asset selection** – choose among preconfigured trading pairs such as BTC/USD, ETH/USD, SOL/USD, ETH/USDC, and BNB.
- **Timeframe-specific topics** – dynamically renders the valid oracle topics (e.g. 5 minute, 8 hour, 1 day) per asset.
- **Live price vs. prediction** – fetches market prices from the CoinGecko API and compares them against Allora inference results.
- **Expected change indicator** – highlights the percentage difference and direction between the prediction and the current price.
- **Automatic refresh** – polls data every 30 seconds with inline status messaging for success and error states.
- **Responsive Tailwind UI** – modern, mobile-friendly layout powered by Tailwind CSS via CDN.

## Tech Stack
- **HTML + Vanilla JavaScript** for the single-page application logic.
- **Tailwind CSS** (loaded from CDN) for styling and layout utilities.
- **Allora Network API** for prediction data (`/v2/allora/consumer/{chainId}`).
- **CoinGecko Simple Price API** for live market prices.

## Getting Started
1. **Clone the repository**
   ```bash
   git clone https://github.com/<your-account>/allora-price-prediction.git
   cd allora-price-prediction
   ```
2. **Start a static file server (recommended)**
   Serve the `index.html` file to avoid CORS limitations when testing API calls locally:
   ```bash
   # Option A: Python
   python -m http.server 8080

   # Option B: npm (requires Node.js)
   npx serve
   ```
3. **Open the app**
   Visit `http://localhost:8080` (or the port reported by your server) in your browser. The dashboard loads with the default BTC/USD 1 day selection and begins polling data automatically.

> **Tip:** You can also double-click `index.html` to open it directly in your browser, but API requests may be blocked by certain browsers due to CORS policies.

## Configuration
All user-facing behaviour is defined at the top of `index.html`:
- `ALLORA_API_KEY` – the API key passed to the Allora consumer endpoint. Replace the placeholder with your own key or inject it at build time.
- `CHAIN_ID` – chain context used when calling Allora (default: `ethereum-11155111`).
- `REFRESH_INTERVAL` – polling interval in milliseconds (defaults to 30 seconds).
- `TOPIC_CONFIG` – mapping of asset symbols to available timeframes, topic IDs, CoinGecko asset IDs, and descriptive labels.

Example snippet:
```js
const TOPIC_CONFIG = {
  "BTC/USD": {
    "1 day": { id: 69, coinGeckoId: 'bitcoin', name: 'BTC/USD - 1 Day Prediction' }
  }
};
```
Add, remove, or modify entries to expose new oracle topics in the UI. Any timeframes that have no configuration are automatically hidden from the selector.

## Data Flow
1. The user selects an asset and timeframe.
2. The app fetches the current market price from CoinGecko using the configured `coinGeckoId`.
3. It requests the latest prediction value from the Allora consumer API using the mapped topic ID and API key.
4. The dashboard calculates the percentage change, updates the summary cards, and refreshes the status banner and “Last Updated” timestamp.

## Production Considerations
- **Protect your API key.** The current implementation embeds the Allora API key directly in the client. For production deployments, proxy the request through a backend service or inject the key during build to avoid exposing credentials.
- **Rate limits.** Both Allora and CoinGecko enforce rate limits. Adjust `REFRESH_INTERVAL` or add caching if you expect higher traffic.
- **Error handling.** The UI displays inline status messages for API failures. Enhance the logging or add retry logic if you need stricter reliability.
